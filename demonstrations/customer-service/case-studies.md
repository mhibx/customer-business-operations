# Case Studies

> **Classification:** Demonstration scenarios.  
> Customer messages, transaction information, and outcomes are examples created for portfolio purposes.

## Case 01 — Gaming Top-Up Not Received

### Situation

A customer completes a Mobile Legends top-up but the diamond/item has not appeared in the game account.

### Customer Message

> "Kak, saya sudah bayar tapi diamond belum masuk."

### Investigation

The support process should:

1. Request the transaction details.
2. Verify the product and amount.
3. Check payment status.
4. Verify the game/user ID.
5. Check the transaction-processing status.
6. Determine whether the issue is related to payment, order processing, or delivery.
7. Provide an update to the customer.
8. Follow up until the case is resolved or appropriately escalated.

### Example Response

> "Baik Kak, mohon maaf atas kendalanya. Saya bantu cek terlebih dahulu ya. Mohon kirimkan nomor transaksi atau bukti pembayarannya serta ID game yang digunakan. Setelah saya cek, saya informasikan status transaksinya."

### Possible Resolution

If the transaction is still processing, provide the current status and an appropriate update.

If the transaction failed while payment was successful, the case can be investigated or routed through the applicable refund/reprocessing procedure.

## Case 02 — Wrong Free Fire Player ID

### Situation

A customer purchases Free Fire diamonds but provides an incorrect player ID.

### Investigation

Check:

- Transaction ID
- Product purchased
- Amount
- Submitted player ID
- Transaction status
- Whether the transaction has already been completed

### Decision Logic

If the transaction has not been processed, a data change may be considered if the applicable procedure allows it.

If the transaction has already been successfully delivered to the submitted ID, the customer should be informed based on the transaction facts and applicable service policy.

### Communication Principle

The objective is to resolve or explain the issue professionally without immediately blaming the customer.

## Case 03 — Digital Token Not Received

### Situation

A customer purchases a digital electricity token but reports that the token has not been received.

### Investigation Flow

```text
Payment Confirmation
        ↓
Transaction Status
        ↓
Product / Token Generation
        ↓
Delivery Status
        ↓
Resolution
```

### Required Information

- Transaction ID
- Payment status
- Product
- Nominal
- Transaction time
- Customer contact
- Transaction result

### Possible Resolution

**Payment successful + transaction successful**

→ Verify token delivery and resend the information if applicable.

**Payment successful + transaction pending**

→ Monitor the transaction status and provide an update.

**Payment successful + transaction failed**

→ Investigate the transaction and follow the applicable refund/reprocessing procedure.

---

## General Investigation Principle

The purpose of investigation is to identify the actual failure point before communicating a resolution.

```text
Customer Report
      ↓
Collect Information
      ↓
Verify Transaction
      ↓
Identify Failure Point
      ↓
Resolve / Escalate
      ↓
Update Customer
      ↓
Follow-up
```
